# Severity comparisons match the stored case

## What was built

- The rule DSL's `severity` field compiles to `lower(cves.severity)`.
- `DigestCVEs` filters and ranks on `lower(severity)`.
- The `GET /cves` severity filter lowercases its input and compares with `lower(cves.severity)`, so `critical` and `CRITICAL` both work.
- `TestExecuteDSLQuery_SeverityMatchesStoredCase`, `TestDigestCVEs_SeverityMatchesStoredCase` and `TestListCVEs_SeverityFilterMatchesStoredCase`, plus pitfall ARCH-46.

## Key decisions

- Compared at query time rather than normalizing stored values. `material_hash` includes severity, so changing stored values would change hashes and fire alerts for every matching rule. This also needs no migration and leaves the API's response values as they are.
- The `cves_severity_idx` index no longer serves these comparisons. Evaluator queries are already limited by CVE ID, and `GET /cves` and `ExecuteDSLQuery` read in keyset order. No new index was added without a measured need.

## Gotchas

- Store tests seeded lowercase values and API tests seeded and queried uppercase ones, so each agreed with itself while the components disagreed.
- Before this change, a rule on `severity eq critical` matched no NVD-scored CVE, a digest with a severity threshold left out all of them, and the web UI's severity filter returned nothing. Each reported success.
- The GHSA adapter's comment says "normalize to uppercase" above a `strings.ToLower` call. The code is left as it is, because changing it would change `material_hash` for GHSA-only CVEs.
- API responses still show severity in the stored case, so a client can see both `HIGH` and `high`.

## Quality checks

- The three new tests failed before the change and pass after it.
- `go test` passes for `internal/alert`, `internal/store`, `internal/api`, `internal/notify` and `internal/ai`.
- On a local production stack with live NVD data, through a client generated by `oapi-codegen` v2.8.2 and authenticating with an API key: the severity rule's dry run matched 75 CVEs, and the filter returned scored CVEs.
