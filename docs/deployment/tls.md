# TLS Configuration

CVErt Ops relies on a reverse proxy for TLS termination. This document covers common configurations.

## Option 1: Caddy (Recommended)

Caddy is included in the Docker Compose setup and provides automatic TLS via Let's Encrypt.

### Setup

1. Set the `CADDY_HOST` environment variable to your domain:

```bash
CADDY_HOST=cvert.example.com
EXTERNAL_URL=https://cvert.example.com
```

2. Start with the production overlay:

```bash
docker compose -f docker/compose.yml -f docker/compose.prod.yml \
  --profile app --env-file .env up -d
```

Caddy automatically obtains and renews TLS certificates from Let's Encrypt. No manual certificate management required.

### Requirements

- Port 80 and 443 must be reachable from the internet (for ACME HTTP-01 challenge)
- DNS A/AAAA record pointing to your server

### Custom Caddyfile

To customize Caddy's behavior, mount a custom Caddyfile:

```yaml
# In docker-compose.override.yml
services:
  caddy:
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
```

## Option 2: nginx

### Configuration

```nginx
server {
    listen 443 ssl http2;
    server_name cvert.example.com;

    ssl_certificate     /etc/letsencrypt/live/cvert.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/cvert.example.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

server {
    listen 80;
    server_name cvert.example.com;
    return 301 https://$host$request_uri;
}
```

### Certificate Management with Certbot

```bash
# Install certbot
apt install certbot python3-certbot-nginx

# Obtain certificate
certbot --nginx -d cvert.example.com

# Auto-renewal (certbot installs a timer/cron automatically)
certbot renew --dry-run
```

## Option 3: AWS Application Load Balancer

### Setup

1. Create an ALB with an HTTPS listener on port 443
2. Attach an ACM certificate for your domain
3. Configure a target group pointing to port 8080 on your instance
4. Set the health check path to `/healthz`

### CVErt Ops Configuration

```bash
EXTERNAL_URL=https://cvert.example.com
COOKIE_SECURE=true
TRUSTED_PROXIES=10.0.0.0/8    # Your VPC CIDR
```

## Option 4: Azure Application Gateway

### Setup

1. Create an Application Gateway with an HTTPS frontend
2. Upload or reference a Key Vault certificate
3. Configure a backend pool with port 8080
4. Set the health probe path to `/healthz`

### CVErt Ops Configuration

```bash
EXTERNAL_URL=https://cvert.example.com
COOKIE_SECURE=true
TRUSTED_PROXIES=10.0.0.0/8    # Your VNet CIDR
```

## Trusted Proxies

When behind a reverse proxy, set `TRUSTED_PROXIES` to ensure CVErt Ops reads the correct client IP from `X-Forwarded-For` headers:

```bash
# Docker bridge network
TRUSTED_PROXIES=172.16.0.0/12

# Multiple ranges (comma-separated)
TRUSTED_PROXIES=172.16.0.0/12,10.0.0.0/8
```

Without this setting, rate limiting and audit logging may record the proxy's IP instead of the client's.

## PostgreSQL TLS

The dev setup uses self-signed certificates for Postgres TLS (generated by `docker/postgres-tls/generate-cert.sh`).

For production PostgreSQL:
- Use certificates from a trusted CA or your organization's PKI
- Set `sslmode=verify-full` in `DATABASE_URL` for certificate validation
- Mount certificates into the Postgres container or use a managed database service

```bash
DATABASE_URL=postgres://cvert:password@db:5432/cvert_ops?sslmode=verify-full&sslrootcert=/certs/ca.crt
```

## Verifying TLS

```bash
# Check certificate
openssl s_client -connect cvert.example.com:443 -servername cvert.example.com < /dev/null 2>/dev/null | openssl x509 -noout -dates

# Check HTTPS connectivity
curl -v https://cvert.example.com/healthz
```
